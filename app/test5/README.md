# PhonePe Payment Gateway Integration

This folder contains a complete integration of PhonePe Standard Checkout API for testing and production use.

## Features

- ✅ Authorization API integration
- ✅ Create Payment API
- ✅ Order Status API
- ✅ Refund API
- ✅ Refund Status API
- ✅ Payment Callback Handler
- ✅ Modern UI with React components
- ✅ Full TypeScript support

## Prerequisites

Before using this integration, ensure you have:

1. **PhonePe Merchant Account** - Access to PhonePe PG's UAT (Sandbox) and Production environments
2. **API Credentials** from PhonePe dashboard:
   - Client ID
   - Client Secret
   - Client Version
   - Merchant ID
   - Salt Key
   - Salt Index

## Environment Variables Setup

Add the following environment variables to your `.env.local` file:

```env
# PhonePe Configuration
PHONEPE_CLIENT_ID=your_client_id
PHONEPE_CLIENT_SECRET=your_client_secret
PHONEPE_CLIENT_VERSION=1.0
PHONEPE_MERCHANT_ID=your_merchant_id
PHONEPE_SALT_KEY=your_salt_key
PHONEPE_SALT_INDEX=1
PHONEPE_ENVIRONMENT=sandbox  # or 'production'
PHONEPE_REDIRECT_URL=http://localhost:3001/test5/callback
PHONEPE_CALLBACK_URL=http://localhost:3001/api/phonepe/callback

# For production, update URLs:
# PHONEPE_REDIRECT_URL=https://yourdomain.com/test5/callback
# PHONEPE_CALLBACK_URL=https://yourdomain.com/api/phonepe/callback
```

## API Endpoints

### 1. Authorization
**POST** `/api/phonepe/auth`

Get OAuth token for PhonePe API authentication.

### 2. Create Payment
**POST** `/api/phonepe/payment`

Request body:
```json
{
  "merchantTransactionId": "TXN1234567890",
  "merchantUserId": "USER123",
  "amount": 100.00,
  "mobileNumber": "9876543210",
  "paymentInstrument": {
    "type": "PAY_PAGE"
  }
}
```

### 3. Order Status
**GET** `/api/phonepe/status/[orderId]`

Check the status of a payment order.

### 4. Refund
**POST** `/api/phonepe/refund`

Request body:
```json
{
  "originalTransactionId": "PHONEPE_TXN_ID",
  "merchantUserId": "USER123",
  "merchantRefundId": "REF1234567890",
  "amount": 100.00
}
```

### 5. Refund Status
**GET** `/api/phonepe/refund-status/[refundId]`

Check the status of a refund.

### 6. Callback Handler
**POST/GET** `/api/phonepe/callback`

Receives payment status updates from PhonePe. Update this handler to:
- Verify callback signature
- Update your database
- Send notifications
- Handle business logic

## Usage

1. **Start the development server:**
   ```bash
   npm run dev
   ```

2. **Navigate to the test page:**
   ```
   http://localhost:3001/test5
   ```

3. **Test Payment Flow:**
   - Enter amount and payment details
   - Click "Proceed to Payment"
   - You'll be redirected to PhonePe payment page
   - Complete the payment
   - Check order status using the transaction ID

## Payment Methods Supported

- **PAY_PAGE**: All payment methods (UPI, Cards, Net Banking)
- **UPI**: UPI payments only
- **CARD**: Credit/Debit cards only
- **NET_BANKING**: Net Banking only

## Important Notes

1. **Amount Format**: All amounts should be in paise (₹1 = 100 paise). The API automatically converts rupees to paise.

2. **Transaction IDs**: 
   - Merchant Transaction ID: Unique ID generated by your system
   - PhonePe Transaction ID: Returned by PhonePe after payment

3. **Security**:
   - Never expose your Client Secret or Salt Key in frontend code
   - Always verify callback signatures in production
   - Use HTTPS in production

4. **Testing**:
   - Always test in Sandbox environment first
   - Use test credentials provided by PhonePe
   - Verify all payment flows before going to production

## Troubleshooting

### Common Issues

1. **"PhonePe credentials not configured"**
   - Check that all environment variables are set correctly
   - Restart the development server after adding env variables

2. **"Failed to get authorization token"**
   - Verify Client ID and Client Secret are correct
   - Check if you're using the right environment (sandbox/production)

3. **"Payment URL not received"**
   - Check Salt Key and Salt Index configuration
   - Verify Merchant ID is correct
   - Check PhonePe dashboard for API access permissions
